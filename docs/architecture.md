# アーキテクチャ

本書は [requirements.md](requirements.md) を実現するための構成と技術判断を定義する。
品質境界と受入条件は [quality-and-operations.md](quality-and-operations.md) に従う。

## MVP の設計原則

- **ローカルファースト**: 単一作者の端末で動作し、UI は loopback のみに公開する。
- **段階分離**: 画像解析、AI 生成、決定的最適化、描画を分け、各段階の入出力を保存する。
- **外部 AI の交換可能性**: 提供者固有処理をアダプターへ閉じ込め、モックと保存応答でテストできるようにする。
- **暗黙処理を避ける**: フォント代替、画像送信、文字削除、密度制約緩和は作者へ明示する。
- **再生成より再生を保証**: 外部 AI の同一応答は仮定せず、保存済み応答からの決定的な再生を保証する。

## コンポーネント境界

| コンポーネント | 責務 | 主な出力 |
|---|---|---|
| Project Store | スキーマ版、来歴、中間生成物、編集履歴の保存 | project manifest |
| Image Pipeline | 正規化、前処理、グリッド化、エッジ抽出 | normalized image / density map |
| Font Profiler | フォント実測、欠落グリフ検出、辞書キャッシュ | font profile / density dictionary |
| Vision Adapter | 外部 AI への送信と観察・推測の構造化 | semantic design |
| Text Adapter | 草稿、素材、言い換え候補の生成 | drafts / candidates |
| Optimizer | 文字数制御、候補探索、局所修正、評価 | optimized text / trace |
| Renderer | 同一描画条件でプレビューと最終出力を生成 | PNG / render metadata |
| Authoring UI | 設定、同意、比較、固定、再生成、書き出し | author decisions |

コンポーネント間ではファイルパスだけでなく、内容ハッシュとスキーマ版を渡す。入力または設定が変わった場合は、
依存する後段だけを無効化し、無関係な中間生成物は再利用する。

## 生成アルゴリズム

### 第1段階: 文字密度の離散化
画像の明度を8段階へ分類する。文字も同じ8段階へ分類する。完全一致ではなく隣接する密度クラスの文字も候補に含める。

```
レベル0：ほぼ白    レベル4：中間
レベル1：非常に薄い レベル5：やや濃い
レベル2：薄い      レベル6：濃い
レベル3：やや薄い  レベル7：非常に濃い
```

### 第2段階: 意味的な草稿生成
画像解析結果と文字数をLLMへ渡し、通常の文章を生成する。この時点では密度を厳密に合わせない。

### 第3段階: 言い換え候補の生成
各文節について複数の言い換えを生成し、各候補の文字密度列を計算する。

```
光が差し込んでいる
ひかりが入り込んでいる
光線が室内を横切っている
明るさが窓から流れ込む
```

### 第4段階: 組み合わせ探索
密度マップに最も近い文節の組み合わせを探索する。候補: 動的計画法 / ビームサーチ / 遺伝的アルゴリズム / 焼きなまし法 / 局所探索。**MVP ではビームサーチまたは局所探索**。

### 第5段階: 局所修正
密度誤差が大きい区間（20文字前後）だけをLLMへ再入力し、意味を維持したまま書き換える。

### 第6段階: 最終レンダリング
文章をグリッドへ配置し、視覚評価を行う。

### 改訂版（カットアップ対応）
```
1. 写真から密度マップを作る
2. 密度マップを読み順に沿った波形へ変換する
3. 写真から複数の文章素材を生成する
4. 文章素材を文字・語・文節へ分解する
5. 各断片の視覚密度と書体リズムを測定する
6. 密度波形へ適合するように断片を配置する
7. 必要に応じて語を言い換える
8. 文法秩序パラメータに応じて接続を修復または破壊する
9. 光学的評価と文章評価を行う
10. 結果をレンダリングする
```
AIは詩人であると同時に文章素材の供給者となり、最終的な構成は写真の光学構造と探索アルゴリズムが担う。

## 実装上の重要課題

### 自然な文章と文字密度は直接両立しにくい
LLMは語・トークン単位で生成する一方、視覚制約は文字単位で存在する。日本語のLLMトークンと表示文字は一対一ではないため、プロンプトだけでの正確な制御は難しい。→ 二段階構成（LLMによる意味生成 → アルゴリズムによる文字密度最適化）。

### 漢字への置換だけでは文章が不自然になる
暗い場所をすべて難しい漢字にすると過剰に硬くなる。併用手法: 漢字表記とひらがな表記の切り替え / 同義語置換 / 語順変更 / 文末表現変更 / 句読点調整 / 修飾語の追加削除 / 文節単位の再生成。

### 画像の局所構造が失われる
平均密度だけを合わせても輪郭が崩れる。将来的に文字ごとに左右・上下半分の密度 / エッジ方向 / 黒画素の重心を評価し、形状の近い文字を選ぶ。

## データ構造の方針

将来的に光学的韻律と音韻的韻律を重ねるため、以下を保存できる構造にする。
- 文章（最終・草稿）
- 文字ごとの密度・書体・文字種
- 読み・品詞情報
- 生成条件（プロンプト / モデル / シード / フォント / レンダリング設定）
- 意味設計データ（FR-05）
- 意味マップ（明暗と意味の対応）

プロジェクトの manifest は、入力ハッシュ、各段階の成果物 ID、フォントハッシュ、モデル識別子、
設定、シード、アプリ版、スキーマ版を持つ。画像や大きな中間生成物はファイルとして保存し、
SQLite は索引・履歴・評価に使う。保存は一時ファイルへの書込み後に置換し、途中失敗で有効版を壊さない。

## 外部依存と失敗時の方針

- 外部 AI 呼出しにはタイムアウト、取消、上限付き再試行を設け、認証・制限・障害を区別する。
- 画像解析に失敗した場合は、作者が意味設計データを手入力して後段を続行できる。
- 文章生成に失敗した場合は、作者入力文または保存済み草稿から最適化を続行できる。
- フォントまたはグリフが不足する場合は描画を停止し、暗黙の代替フォントを使わない。
- ログは工程、時間、識別子、評価値に限定し、API キーと不要な本文を記録しない。
- 外部 AI アダプターはネットワークなしの保存応答モードを備え、受入テストを安定させる。

### 意味マップ（将来拡張）
単に暗部へ濃い文字を置くだけでなく意味も対応させる。
```
暗部：記憶、影、閉塞、重さ、沈黙
明部：光、呼吸、空白、消失、開放
輪郭：境界、皮膚、窓、距離
顔：一人称、身体、感情
背景：時間、場所、過去の記述
```

### 領域別語彙（将来拡張）
セグメンテーションを用いて画像領域ごとに語彙を指定する。
```
人物領域：身体、記憶、感情
空領域：時間、光、天候
建物領域：構造、部屋、都市
影領域：不在、死、沈黙
```
