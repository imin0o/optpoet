# 品質・運用要件

本書は [requirements.md](requirements.md) の機能を、安全かつ検証可能に提供するための正規情報源である。
数値は MVP の暫定基準であり、Phase 0 のベースライン計測で更新する。

## 1. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 再現・再生 | ローカルの決定的工程は同一入力で同一結果にする。外部 AI は応答原文を保存し、その応答を再生した場合の最終出力を一致させる |
| NFR-02 描画一貫性 | 密度辞書と最終出力で同じフォントファイル、描画エンジン、バージョン、設定を使う |
| NFR-03 編集可能性 | 草稿、画像解釈、語句、領域、重みを作者が修正・固定でき、変更の影響範囲を示す |
| NFR-04 性能 | 参照環境でプレビュー 5 秒以内、2,000 セル 3 分以内、5,000 セル 10 分以内を目標とする |
| NFR-05 中断耐性 | 長時間工程を中断・再開でき、完了済み工程をキャッシュから再利用する |
| NFR-06 保存性 | プロジェクトを閉じて再読込しても入力、設定、中間生成物、編集、出力、来歴を失わない |
| NFR-07 互換性 | MVP の参照環境は Windows 11 x64 とし、他 OS は検証後に対応対象へ加える |
| NFR-08 可観測性 | 工程時間、モデル、再試行、評価値を記録するが、API キーや不要な画像・文章本文はログへ出さない |

性能時間は外部 AI の待ち時間を含む。参照 PC、回線、モデル、日時、セル数を計測結果とともに記録し、
外部サービス障害は性能不合格ではなく可用性事象として分ける。

## 2. 再現性の定義

外部 AI は同じモデル名とシードでも同一応答を保証しない場合があるため、再現性を二段階に分ける。

- **再生成**: 同じ条件で外部 AI を再度呼ぶ。意味的に近いが同一結果とは限らない。
- **再生**: 保存済み AI 応答と中間生成物から決定的工程だけを実行する。最終 TXT と PNG は一致必須。

プロジェクトにはモデル提供者、モデル識別子、呼出設定、応答、フォントハッシュ、描画エンジン、
アプリ版、スキーマ版を保存する。

## 3. プライバシーとセキュリティ

- 画像・文章を外部 AI へ送る前に、送信先、送信内容、目的を作者へ表示し、明示設定なしに送信しない。
- 外部送信用画像から位置情報、撮影機器情報など不要な EXIF を除去する。
- API キーは OS の資格情報保管または環境変数で扱い、プロジェクト、ログ、出力へ保存しない。
- MVP の UI は loopback のみにバインドし、LAN やインターネットへ公開しない。
- ファイル名と外部応答を命令として実行せず、出力パスは作者が選んだ作業領域内へ制限する。
- クラッシュ報告や利用分析は MVP では外部送信しない。

将来 UI を外部公開する場合は、認証、認可、CSRF、レート制限、保存期間、削除要求を別要件として追加する。

## 4. 権利と来歴

- 作者は入力写真、入力文章、フォントを利用・加工・展示できる権利を確認する。
- カットアップ素材には出典、作者、ライセンスまたは利用根拠を記録する。
- フォントの埋め込み・アウトライン化・再配布条件を出力前に確認できるようにする。
- AI 提供者の利用条件とデータ利用設定をプロジェクト作成時に参照できるようにする。
- エクスポートするプロジェクト JSON では、秘密情報を除外しつつ生成来歴を保持する。

## 5. エラーと回復

| 状況 | 必須挙動 |
|---|---|
| 未対応・破損画像 | 対象、理由、対応形式を示し、プロジェクトを壊さない |
| 欠落フォント・グリフ | 暗黙代替せず、不足文字と影響位置を示す |
| 外部 AI の失敗 | タイムアウト、認証、制限、提供者障害を区別し、保存済み工程から再試行する |
| 文字数不一致 | 書き出しを止め、不足・超過セルと調整候補を示す |
| 保存容量不足 | 一時ファイルを最終成果として扱わず、直前の有効版を保持する |
| スキーマ不一致 | 読取専用で開くか移行案を示し、元ファイルを上書きしない |

## 6. 検証用データセット

MVP 判定用に、権利を確認した固定写真を最低 12 枚用意する。

- 人物、風景、建築、静物を各 3 枚。
- 高・低コントラスト、細かい輪郭、広い平坦部、逆光を含める。
- 各画像の原本ハッシュ、権利状態、期待する主要構図、難しさを記録する。
- 少なくとも記述、散文詩、簡易カットアップを同一画像から生成する。
- プロンプト、モデル、フォント、設定、シード、評価結果を検証記録に残す。

## 7. 自動受入条件

| ID | 合格条件 |
|---|---|
| AC-01 セル一致 | 全ケースで表示文字数とセル数が一致する |
| AC-02 描画整合 | 欠落グリフと暗黙フォント代替が 0 件 |
| AC-03 視覚改善 | 最適化後の密度 MAE（辞書正規化密度）が草稿配置時より全体中央値で 20% 以上改善する |
| AC-04 再生 | 保存済み AI 応答からの再生で TXT がバイト一致し、PNG が一致する |
| AC-05 保存 | 保存・再読込後に設定、固定箇所、中間生成物、評価値が一致する |
| AC-06 異常系 | 5章の各失敗を模擬し、データ喪失なく回復または安全停止する |
| AC-07 性能 | NFR-04 を 12 枚中 10 枚以上で満たし、超過ケースの工程別時間を説明できる |

AC-03 の判定値は密度辞書の正規化密度で測る MAE とする（OI-003、[evaluation-metrics.md](environment/evaluation-metrics.md) 3.1）。
実レンダリング PNG の画素領域で測る MAE に加えて SSIM、エッジ一致率、重要領域の誤差を記録するが、
これらは補助指標として扱い、単一の数値だけで作品の価値を判定しない。

## 8. 人間による評価

記述・散文詩では、作者を含む 3 人以上が次を 5 段階で評価する。

- 遠景で主要構図を識別できる。
- 近景で最後まで読み進められる。
- 写真との意味的関連がある。
- 文体と意図した文法秩序が一致する。
- 文字種・書体の変化が光学的韻律として知覚できる。

MVP の暫定合格は各項目の中央値 3 以上、重大な権利・プライバシー問題 0 件とする。
カットアップは自然さを合格条件にせず、設定した破綻率との一致と作者の意図を評価する。

## 9. 完了の定義

機能は、実装だけでなく次を満たした時点で完了とする。

1. 対応する要件 ID とテストがある。
2. 正常系、境界値、代表的な失敗を検証している。
3. プロジェクト保存・再読込・再生を確認している。
4. 既知の制限と外部依存を文書化している。
5. MVP 受入記録を残している。
