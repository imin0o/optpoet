### 1.1 initial run で見つかった原本の受入上限超過（是正済み）

初回実行時、検証データセットの **architecture-2 は 50,291,940 px** で FR-01 の上限 50MP を超えており、
受入判定が `too_many_pixels` で停止した。初回はこの 1 枚だけ上限内へ縮小した副本（8,652×5,767）で
AC-01〜AC-03 を測り、逸脱として記録した。

[OI-005](../decisions/open-issues.md) の決定により、上限は要件のまま維持し、architecture-2 の枠を
同一作者・同一主題・CC0 の 50MP 未満原本（Chester Cathedral Nave.jpg、5,929×5,757 = 34,133,253 px）へ
差し替えた。旧原本は [validation-dataset.md](validation-dataset.md) 4.2 に上限超過ケース用として残し、
P1-G03 の `too_many_pixels` はこの原本で確認している。再実行では 12 枚すべてが縮小なしで受け入れられた。

### 3.2 P1-G02（AC-03 の測定と記録）— 合格

- 5,000 セルも同傾向（密度領域 +0.89% / 画素領域 +0.06%）。除外（`MAE_draft = 0`）は両サイズとも 0 枚。
- 探索記録は 24 ケースすべてに残る（採用件数 2,000 セルで 310〜412 件、5,000 セルで 672〜897 件。
  反復はいずれも 2 回で `converged`）。
- 補助指標の中央値: SSIM 0.314（2,000）/ 0.380（5,000）、エッジ一致率 0.008（2,000）/ 0.002（5,000）。

**AC-03 の 20% に届かない理由は 2 つあり、いずれも最適化の実装品質ではない。**

1. **画素領域の尺度差（構造的な上限）**: 文字の黒画素率は基準フォント・基準セルで 0.000〜0.153。
   一方、目標画像のセル密度は 0.0〜1.0 を使う。密度だけで各セルの文字を自由に選ぶ基準配置
   （P1-034、意味を無視した理論上の下限）でも、portrait-3 の画素領域 MAE は **0.5145**
   （目標平均密度 0.602）で、草稿配置 0.5725 からの改善は 10% 程度が上限。同じ基準配置を密度領域
   （辞書内の最小〜最大で正規化した尺度）で測ると MAE は 0.0003 で、改善余地がほぼ 100% ある。
   この観測が [OI-003](../decisions/open-issues.md)（判定値を密度領域へ）の根拠になった。
2. **Phase 1 の置換候補が狭い**: 局所探索が使えるのは表記候補だけで、既定表はかな⇔カナ・約物・空白の
   相互置換のみ（`text/variants.py`。意味が変わる同義語・漢字⇔かなは形態素解析が要るため Phase 2 の担当）。
   採用件数は上記のとおりで探索は 2 反復で収束（`converged`）。候補が尽きており、反復回数や停止条件を
   緩めても伸びない。これが [OI-004](../decisions/open-issues.md)（20% 判定を P2-G01 へ）の根拠。

### 3.3 P1-G03（異常系の安全停止）— 合格

| 事象 | 入力 | 停止 | 工程 / 区分 |
| --- | --- | --- | --- |
| 破損画像 | portrait-3 を先頭 20% で切断 | 構造化エラー | normalize / `corrupted` |
| 画素上限超過 | 上限超過用原本（50,291,940 px、[validation-dataset.md](validation-dataset.md) 4.2） | 構造化エラー | normalize / `too_many_pixels` |
| 容量上限超過 | still-life-1 に詰め物をして 100MB 超 | 構造化エラー（復号前） | normalize / `too_large_bytes` |
| 欠落グリフ | フォント未収録の字（U+0915 / U+AC00 / U+1F600） | 構造化エラー（描画前） | dictionary / `missing_glyph` |
| 許可文字集合外 | 全角英字・絵文字を含む本文 | 構造化エラー（入力時） | text / `unsupported_chars` |
| 容量不足 | manifest 書込みで ENOSPC を模擬 | `StorageError` で中止 | 保存（A-08） |

容量不足では、**直前の有効版が保持された**ことまで確認した。中止後に開き直すと
`open_mode = normal`、manifest の `updated_at` は失敗前と同一、保存済み成果物からの
再生も一致した。データ喪失なし。

### 3.4 P1-G04（AI なしの保存・再読込・再生）— 合格

portrait-3 / 2,000 セルで、最適化後の成果物を保存 → 開き直し → manifest だけを頼りに再生。

- `ai_calls` は 0 件（AI 応答を使わずに再生）。
- 再生した TXT は保存した TXT と**バイト一致**、PNG も**バイト一致**（`replay.matches = true`）。
- 保存済み manifest から復元した配置は元の配置と一致。`outputs.render_metadata` は
  辞書と同じ描画設定（I-03）。`evaluation.cell_check` は 2,000 / 2,000 / ok。
- 全 ref の実体存在とハッシュ一致（I-02）を保存後に検証。

中央値（12 枚、秒）。密度辞書の構築は全ケース共有で 0.56 秒（6,560 字）。

## 5. 再現手順

1. `python gates/p1/fetch_assets.py` — 12 画像＋上限超過用 1 枚と入力文を取得し、SHA-256 が
   [validation-dataset.md](validation-dataset.md) 4章・4.2 および 1章の記録と一致することを確認する
   （不一致なら停止する）。
2. `python gates/p1/run_gate.py` — `out/gate-2000-5000.json` にケース別の cell_check・欠落グリフ・
   両尺度の指標・工程別時間と、辞書の正規化条件を書き出す。
3. `python gates/p1/run_abnormal.py` — `out/abnormal.json`。
4. `python gates/p1/run_replay.py` — `out/replay.json`。

2〜4 は乱数を使わず、同じ入力・同じ設定なら同じ値を返す（NFR-01）。工程別時間とピーク作業セットは
実行環境に依存する。
