# 外部 AI 能力のプロバイダー非依存定義

**状態**: 定義済み（2026-07-25）。具体プロバイダーの選定は [P0-021](../roadmap/phase-0.md) 以降で行う。
**目的**: 画像解析と文章生成に本ツールが必要とする能力を、特定プロバイダー・特定 API に依存しない形で定義する。後続の候補評価（[P0-021](../roadmap/phase-0.md)）、費用上限（[P0-022](../roadmap/phase-0.md)）、失敗応答（[P0-023](../roadmap/phase-0.md)）、アダプター契約（[P0-024](../roadmap/phase-0.md)）が同じ能力語彙で議論できるようにする。
**対象タスク**: [P0-020](../roadmap/phase-0.md)
**関連**: [architecture.md](../architecture.md)（Vision/Text Adapter、段階分離、再生保証）、[requirements.md](../requirements.md)（FR-05 / FR-08 / FR-09 / FR-15、NFR）、[quality-and-operations.md](../quality-and-operations.md)、[open-issues.md](open-issues.md)

本書は「どのモデルを使うか」ではなく「モデルに何を要求するか」を固定する。アーキテクチャは提供者固有処理をアダプターへ閉じ込め、モックと保存応答でテスト可能にする方針（[architecture.md](../architecture.md) の交換可能性）であり、本書はそのアダプター境界の**外向き要求仕様**にあたる。

## 能力の分類

本ツールが外部 AI に求める能力は 2 系統に限定する。両者は独立に交換・モック・保存応答化できる。

| 能力 | アダプター | 対応 FR | 段階 |
| --- | --- | --- | --- |
| C-VISION 画像解析 | Vision Adapter | FR-05 | 第2段階前段（写真内容の解析） |
| C-TEXT 文章生成 | Text Adapter | FR-08 / FR-09 / FR-15 | 第2〜3段階（草稿・素材・言い換え） |

決定的最適化・密度測定・描画はローカル処理であり、外部 AI 能力には含めない（[architecture.md](../architecture.md) の段階分離）。文字単位の密度制御を AI に要求しない（[architecture.md](../architecture.md): トークンと表示文字が一対一でないため二段階構成を採る）。

## C-VISION 画像解析能力

### 要求

- **入力**: 1 枚の静止画（作者が前処理・トリミング済み、EXIF 除去済み: FR-01）と、抽出観点の指示。マルチモーダル（画像＋テキスト指示）入力を受け付けること。
- **出力（構造化）**: 被写体・空間・光・構図・動作・色調・雰囲気・象徴候補を分離した構造データ（FR-05）。自由文の一塊ではなく、観点ごとに区切れる形式で返せること。
- **事実と解釈の分離**: 「観察できる事実」と「推測・詩的解釈」を別フィールドで返せること（FR-05）。この分離は後段で作者が編集・固定するための前提。

### 必須挙動・制約

1. **身元・センシティブ属性を推定しない**: 人物の身元やセンシティブ属性を画像だけから推定させない（FR-05、[quality-and-operations.md](../quality-and-operations.md) のプライバシー要件）。指示側でこの抑制を明示できること。
2. **画像送信の明示性**: 画像を外部へ送る処理は暗黙に行わない（[architecture.md](../architecture.md): 暗黙処理を避ける）。送信有無は作者へ提示する（FR-18）。
3. **構造の安定性**: 同一観点セットに対し、常に同じフィールド構成で返す（欠測時は空値で明示）。パース不能な自由文の混入を許容しない。

### 失敗時フォールバック

- 画像解析に失敗した場合、作者が意味設計データ（semantic design）を手入力して後段を続行できる（[architecture.md](../architecture.md) の degrade 方針、FR-18）。すなわち C-VISION は**必須依存ではなく代替可能**とする。

## C-TEXT 文章生成能力

### 要求

- **入力**: 意味設計データ（C-VISION 出力または作者入力）、目標文字数（＝セル数の目安、FR-10）、文章モード（記述／散文詩／簡易カットアップ: FR-06）、および言い換え要求。
- **出力（3 用途）**:
  1. **意味的な草稿**（1 本、密度は厳密に合わせない: [architecture.md](../architecture.md) 第2段階、FR-09-1）。
  2. **複数の文章素材**（カットアップ／探索用の供給: FR-09-1、FR-15、[concept.md](../concept.md) の「素材の供給者」）。
  3. **言い換え候補**（文節単位、位置を保った複数案: FR-09-2）。密度最適化の探索空間を作る中核。
- **日本語**: 日本語の生成品質を満たすこと（MVP は日本語のみ、[requirements.md](../requirements.md) 対象外に多言語なし）。

### 必須挙動・制約

1. **文字単位の密度制御を要求しない**: `visual_similarity` 等の視覚制約充足は AI ではなくローカル探索が担う（FR-08、[architecture.md](../architecture.md)）。AI へは「意味・文体・言い換えの多様性」だけを要求する。
2. **言い換えの多様性と位置保持**: 同一文節に対し複数の表記・語順・文末・修飾の候補を返せること（[architecture.md](../architecture.md) の併用手法: 漢字↔ひらがな／同義語／語順／文末／句読点／修飾増減）。位置（文節境界）は形態素解析側で保持する（[morphological-analyzer.md](../environment/morphological-analyzer.md)）。
3. **来歴の追跡**: プロンプト・モデル識別子・生成した草稿/候補/採否を後段が記録できる粒度で返す（FR-09-5、FR-17）。

### 失敗時フォールバック

- 文章生成に失敗した場合、作者入力文または保存済み草稿から最適化を続行できる（[architecture.md](../architecture.md)、FR-18）。C-TEXT も**代替可能**とする。

## 横断要件（両能力共通）

プロバイダー非依存を成立させるため、C-VISION / C-TEXT の双方に次を課す。

| ID | 要件 | 根拠 |
| --- | --- | --- |
| X-01 交換可能性 | 提供者固有処理をアダプター内へ閉じ込め、能力境界の入出力形式は本書で固定する。 | [architecture.md](../architecture.md) |
| X-02 保存応答モード | ネットワークなしで保存済み応答から決定的に再生できる（再生成ではなく再生を保証）。 | [architecture.md](../architecture.md)、FR-17、P0-024 |
| X-03 モック可能性 | 実 API なしのモック応答で受入テストを安定実行できる。 | [architecture.md](../architecture.md)、P0-023 |
| X-04 失敗の区別 | タイムアウト・レート制限・認証失敗・サービス障害を区別し、取消と上限付き再試行に対応する。 | [architecture.md](../architecture.md)、FR-18、P0-023 |
| X-05 送信の明示 | 外部送信の有無・対象を作者へ提示し、暗黙送信を禁止する。 | [architecture.md](../architecture.md)、FR-18 |
| X-06 来歴保存 | プロンプト・モデル識別子・入出力を manifest に保存できる形式で返す。 | FR-17、architecture manifest |

X-02・X-03 は「同一応答を仮定しない」という本ツールの前提（[architecture.md](../architecture.md) 第4方針）を実装で担保する要であり、能力定義の一部として扱う。

## 非要求（この能力に求めないもの）

以下は外部 AI に求めない。ローカル処理か MVP 対象外（[requirements.md](../requirements.md) の対象外）。

- 文字単位・トークン単位での視覚密度の厳密制御（→ ローカル探索）。
- 密度マップ生成・文字密度辞書・描画・二値化（→ Pillow ほかローカル）。
- 完全な文字単位 AI 生成、音声、独自大規模モデル学習（→ [requirements.md](../requirements.md) 対象外）。
- 形態素解析（→ SudachiPy、[morphological-analyzer.md](../environment/morphological-analyzer.md)）。
