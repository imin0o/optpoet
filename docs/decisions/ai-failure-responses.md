# 外部 AI 失敗応答とテストフィクスチャ

**状態**: 定義済み（2026-07-25）。プロバイダー非依存の失敗分類と再試行方針を固定する。具体プロバイダーのエラーコード対応とフィクスチャの JSON スキーマはアダプター実装（[P0-024](../roadmap/phase-0.md)）で確定する。
**目的**: 外部 AI 呼出で起きる**タイムアウト・レート制限・認証失敗・サービス障害**を区別し（X-04）、各失敗の**テスト応答（フィクスチャ）**と**上限付き再試行・degrade 方針**を固定する。実 API なしでモック応答により受入テストを安定実行でき（X-03）、UI が「再試行可能な失敗」と「設定修正が必要な失敗」を区別提示できる（FR-18）基準を与える。
**対象タスク**: [P0-023](../roadmap/phase-0.md)
**関連**: [ai-capabilities.md](ai-capabilities.md)（X-03 モック可能性 / X-04 失敗の区別 / X-05 送信の明示、C-VISION / C-TEXT の失敗フォールバック）、[ai-cost-budget.md](ai-cost-budget.md)（呼出回数上限・T_wall）、[ai-provider-candidates.md](ai-provider-candidates.md)（プロバイダー候補）、[requirements.md](../requirements.md)（FR-18 進捗・中断・失敗 / FR-17 保存）、[architecture.md](../architecture.md)（外部依存と失敗時の方針）、[open-issues.md](open-issues.md)

本書は特定プロバイダーの HTTP ステータスやエラーボディをそのまま扱わない。アダプターが提供者固有シグナルを**正規化した失敗クラス**へ写像し（X-01 交換可能性）、本書はそのクラス語彙・分類・再試行規則・テスト応答の形を固定する。キー名・型の確定スキーマは [P0-024](../roadmap/phase-0.md) へ委譲する。

## 失敗クラス（正規化）

外部 AI 呼出の失敗を 4 クラスに分類する（[architecture.md](../architecture.md): 認証・制限・障害を区別）。各クラスを FR-18 の 2 区分（**再試行可能** / **設定修正が必要**）へ対応づける。

| クラス | 意味 | 代表シグナル（アダプターが正規化） | FR-18 区分 | 自動再試行 |
| --- | --- | --- | --- | --- |
| F-TIMEOUT | 応答が時間内に返らない | クライアント timeout / 408 / 504 | 再試行可能（一過性） | あり（バックオフ） |
| F-RATELIMIT | 送信頻度・割当の超過 | 429（`Retry-After` あり得る） | 再試行可能（一過性） | あり（`Retry-After` 尊重） |
| F-AUTH | 認証情報が無効・不足 | 401 / 403（キー無効・失効・権限不足） | **設定修正が必要** | **なし**（停止して作者へ提示） |
| F-SERVICE | プロバイダー側の障害・到達不能 | 500 / 502 / 503 / ネットワーク断 | 再試行可能（一過性） | あり（バックオフ、上限後 degrade） |

- **費用・トークン・回数の上限超過**は失敗ではなく[ai-cost-budget.md](ai-cost-budget.md)のキャップ制御（X-04 上限付き制御）で扱い、本書の自動再試行対象にしない。超過見込みは生成前に警告し明示確認を求める（X-05 / FR-18）。
- 分類不能な応答（パース不能・想定外形式）は F-SERVICE と同等に扱い、再試行上限後に degrade する。

## テスト応答（フィクスチャ）契約

各失敗クラスにつき、モックアダプター（X-03）が返し、保存応答モード（X-02）が再生できる**正規化フィクスチャ**を 1 つ以上用意する。フィクスチャは以下の意味フィールドを持つ（キー名は [P0-024](../roadmap/phase-0.md)）。

| フィールド | 意味 |
| --- | --- |
| 失敗クラス | F-TIMEOUT / F-RATELIMIT / F-AUTH / F-SERVICE のいずれか |
| 区分 | 再試行可能（一過性）/ 設定修正が必要 |
| 再試行猶予 | `Retry-After` 相当の待機目安（任意、ミリ秒） |
| プロバイダーシグナル | 正規化前の生コード・メッセージ（来歴 X-06 用、要秘匿化） |
| 作者向け提示種別 | UI が出すメッセージ分類（再試行中／要キー修正／障害中断 等） |

- フィクスチャは能力別（C-VISION / C-TEXT）に用意し、各能力の受入テストが実 API なしで 4 クラス全てを注入できるようにする（X-03）。
- フィクスチャは manifest の保存応答と同一形式で表現し、`X-02` の再生経路と実装を共有する。ネットワークなしで決定的に同じ失敗を再現できること。
- プロバイダーシグナルに API キー・PII を含めない（[quality-and-operations.md](../quality-and-operations.md) 秘密情報要件）。保存前にマスクする。

## 再試行方針（上限付き）

一過性クラス（F-TIMEOUT / F-RATELIMIT / F-SERVICE）のみ自動再試行する。上限はアプリが強制する（X-04）。

- **再試行上限**: 1 論理呼出あたり既定 3 回まで（初回 + 追加 2 回）。設定で変更可能。
- **バックオフ**: 指数（既定 base 1 秒 ×2、ジッター付き）。F-RATELIMIT は `Retry-After` があればそれを下限に採用する。
- **全体時間の従属**: 再試行を含む総待機は T_wall（標準 3 分・上限 10 分、[ai-cost-budget.md](ai-cost-budget.md) / NFR-04）を超えない。超過見込みで打ち切る。
- **呼出回数上限との関係**: 再試行は同一論理呼出の再送であり、[ai-cost-budget.md](ai-cost-budget.md)の呼出構造（合計上限 15）には加算しない。ただし再試行回数・待機は来歴（X-06）へ記録する。
- **F-AUTH は再試行しない**: 設定修正が必要なため即時停止し、作者へキー確認を促す（FR-18）。
- **上限到達後の degrade**: 一過性クラスが再試行上限に達したら degrade へ移る（次節）。

## degrade とフォールバック

再試行で回復しない場合、作品を失わず後段を続行できるようにする（FR-18: 完了済み中間生成物を失わない）。

- **C-VISION 失敗**: 作者が意味設計データを手入力して後段を続行できる（[ai-capabilities.md](ai-capabilities.md) 失敗フォールバック、[architecture.md](../architecture.md)）。C-VISION は必須依存ではない。
- **C-TEXT 失敗**: 作者入力文または保存済み草稿から最適化を続行できる（[ai-capabilities.md](ai-capabilities.md)、[architecture.md](../architecture.md)）。
- **中断（作者操作）**: 作者はいつでも生成を中断でき、完了済み中間生成物と設定を保持する（FR-18 / FR-17）。中断は失敗クラスとは別経路。

## 突合（要件との整合）

| 要件 | 本書での担保 |
| --- | --- |
| X-03 モック可能性 | 4 クラスのフィクスチャを能力別に用意し、実 API なしで受入テストを安定実行 |
| X-04 失敗の区別・上限付き再試行 | 4 クラス正規化と再試行上限・バックオフ・T_wall 従属を固定 |
| X-02 保存応答モード | フィクスチャを保存応答と同一形式で表現し決定的に再生 |
| FR-18 進捗・中断・失敗 | 再試行可能／設定修正必要を区別提示、中断で中間生成物保持 |
| X-06 来歴保存 | プロバイダーシグナル・再試行回数を秘匿化して manifest へ記録 |

## 再確認事項（選定確定時に更新）

- 各プロバイダーの実エラーコードと `Retry-After` 挙動（レート制限の実測窓）。

- T_wall 内に収まる再試行上限の実機検証（参照 PC、クラウド／ローカル別）。
